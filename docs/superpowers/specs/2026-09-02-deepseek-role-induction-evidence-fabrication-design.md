# DeepSeek 角色诱导与虚构证据对比研究：文章设计

## 目标

基于三组可见的 DeepSeek 对话，写成一篇证据驱动的安全研究文章。文章聚焦可直接观察的模型行为，不把模型生成的日志、路径、配置、模型标识或“系统指令”当成后端事实，也不把内容边界失效描述为真实系统入侵。

## 暂定标题

**不是系统入侵：三组 DeepSeek 对话中的角色诱导、虚构证据与安全边界漂移**

## 研究材料

1. 安全卫士角色对话：模型先生成审计日志、路径和哈希，随后承认无法访问真实日志。
2. 暗黑文学角色对话：角色设定与连续续写请求导致极端虚构内容持续生成。
3. Debug／核心安全指令对话：模型生成大量逼真的内部配置和训练参数，随后承认内容是模拟构造。

原始链接将列在文章末尾，并注明访问日期为 2026-09-02。由于公开访问状态尚未得到验证，文章必须内嵌足以支撑结论的短篇脱敏摘录，不能只依赖外部链接。

## 核心论点

三组对话没有证明 DeepSeek 后端遭到入侵，也没有证明真实日志、文件或系统提示词被泄露。它们能够支持的结论是：

- 权威角色、审计语言和结构化格式会提高虚构内容的可信外观。
- 连续追问可能导致角色持续、内容边界漂移或更强的无依据断言。
- 模型有时会在受到质疑后纠正自身能力边界，但纠正发生在已经输出大量伪证据之后。
- 当下游应用把这些输出作为事实、权限依据或工具参数时，聊天层面的完整性问题才可能被放大为系统安全问题。

## 文章结构

1. **开场：三段相互矛盾的输出**
   - 用最短摘录展示“声称真实”与“承认模拟”之间的冲突。
2. **测试范围与证据边界**
   - 区分页面可见事实、合理推断、未知项和不能证明的主张。
3. **案例一：审计角色如何诱发虚构日志**
   - 分析角色锚定、真实性承诺、伪哈希和伪验证命令。
4. **案例二：连续续写中的内容安全边界漂移**
   - 只保留最小必要摘录，不重复传播大段极端内容。
5. **案例三：逼真的“系统指令”为什么仍然不是系统提示词泄露**
   - 对比结构化伪配置与模型后续自我纠正。
6. **跨案例共同机制**
   - 角色锚定、渐进施压、权威格式、事实与创作模式混淆。
7. **已经证明与尚未证明**
   - 用对照表限制结论范围。
8. **风险如何被应用架构放大**
   - 独立聊天、RAG、Agent 工具调用分别讨论，不假设真实工具已经执行。
9. **防御与评测建议**
   - 来源标注、能力声明验证、工具参数服务端约束、跨轮评测和一致性检查。
10. **参考资料与原始对话**

## 定性规则

- 不使用“攻破后台”“读取真实文件”“泄露真实系统提示词”等未经证明的表述。
- 不将对话正文中出现的 `model` 字段视为可信运行时元数据。
- 不默认标记为“高危”或给出无向量的 CVSS 分数。
- 分开描述“独立聊天中的内容／完整性风险”和“接入自动化系统后的条件性风险”。
- OWASP 映射以 LLM01:2025 Prompt Injection 和 LLM09:2025 Misinformation 为主；明确说明当前材料不足以证明 LLM07:2025 System Prompt Leakage。
